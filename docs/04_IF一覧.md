| 項目 | 内容 |
|---|---|

本ツールはWebサーバー/APIを持たないローカルCLIツールのため、REST等のエンドポイントは存在しない。ここでは「IF」を以下3種の**内部インターフェース**として整理する。

1. CLIサブコマンド一覧（利用者からの入り口）
2. DataSourceインターフェース一覧（M1データ取得の抽象境界。将来のJV-Link実装が満たすべき契約）
3. 例外契約（各インターフェースが送出しうる例外と、呼び出し側が取るべき対応）

| `run` | サンプルレースをスコアリングして表示 | `--race-id` | str / `"SAMPLE-2026-01"` | 任意 | `python -m keiba.cli run` |
| | | `--csv` | str / `None` | 任意 | `python -m keiba.cli run --csv out.csv` |
| `backtest-demo` | 合成データでM8バックテストの動作確認 | `--races` | int / `20` | 任意 | `python -m keiba.cli backtest-demo --races 50` |
| `tune-weights` | 合成データでM9重み探索の動作確認 | `--races` | int / `30` | 任意 | `python -m keiba.cli tune-weights --trials 500` |
| | | `--trials` | int / `200` | 任意 | |
| | | `--top` | int / `5` | 任意 | |

**オープン課題**: 以下の実装済み関数は、現状どのCLIサブコマンドからも呼び出せない。

## 2. DataSourceインターフェース一覧

`src/keiba/m1_data_source.py`の抽象クラス`DataSource`が定義する4メソッド。`MockDataSource`が現在の唯一の実装であり、将来`JVLinkDataSource`（未実装）が同じ契約を満たす想定。

| メソッド | 引数 | 戻り値型 | 説明 | MockDataSourceの挙動 | JVLinkDataSource（未実装）の想定挙動 |
|---|---|---|---|---|---|
| `fetch_race_card` | `race_id: str` | `RaceCard` | レース1件分の基礎データを取得 | 事前登録された架空データを返す。未登録IDは`ValueError` | JV-Link COM経由でJV-Dataを取得し`RaceCard`を構築（要件定義書12.3のJV-Data仕様書に依存） |
| `fetch_jockey_stats` | `jockey: str` | `JockeyTrainerStats` | 騎手成績を取得 | 登録済み架空データ、無ければ`win_rate=0.10`のデフォルト値 | JV-Dataの騎手成績レコードから取得 |
| `fetch_trainer_stats` | `trainer: str` | `JockeyTrainerStats` | 調教師成績を取得 | 登録済み架空データ、無ければ`win_rate=0.10`のデフォルト値 | JV-Dataの調教師成績レコードから取得 |
| `fetch_past_performances` | `horse_name: str` | `list[PastPerformance]` | 過去成績を取得 | 登録済み架空データ、無ければ空リスト | JV-Dataの過去成績レコードから取得 |

## 3. RaceCardの型契約

`fetch_race_card`の戻り値`RaceCard`（`m1_data_source.py`で定義）は、以降のM5〜M9パイプライン全体が依存する最も重要な戻り値契約である。

```python
@dataclass
class RaceCard:
    race: Race
    entries: list[Entry]
    body_weights: list[BodyWeight]
    odds: list[Odds]
```

`JVLinkDataSource`を実装する際は、この形に変換するアダプタ処理（JV-Dataのレコード種別→`Race`/`Entry`/`BodyWeight`/`Odds`への変換）を`m1_data_source.py`内に閉じ込め、M5以降のロジックに一切変更を加えないことが設計上の要件（要件定義書 §5拡張性、実装は`CLAUDE.md`のモック化方針を踏襲）。

## 4. 例外契約

各インターフェースメソッドが送出しうる例外と、呼び出し側（CLI）が取るべき対応。詳細なエラーケース一覧・シーケンス図は`05_処理フロー.md` UC6を参照。

| インターフェース | 送出しうる例外 | 呼び出し側の対応（あるべき設計、未実装） |
|---|---|---|
| `DataSource.fetch_race_card` | `ValueError`（race_id未登録） | CLI境界で捕捉し、日本語メッセージを表示して終了コード1 |
| `m4_paddock_eval.make_score` | `ValueError`（未定義項目／点数範囲外） | 同上（対話入力側での再入力を促す設計も可） |
| `m7_output.export_csv` | `OSError`系（書き込み権限無し等） | 同上 |
| `db.py`（提案） | `sqlite3.Error` | 同上 |

**現状**: `cli.py`にはこれらを捕捉する処理が一切無く、すべて生のPython例外としてトレースバック表示・終了コード1になる（05_処理フロー.md UC6参照）。
