# セキュリティ設計

| 項目 | 内容 |
|---|---|
| 更新日 | 2026-08-07 |

## 1. JRA-VAN認証情報の管理

将来`JVLinkDataSource`を実装する際、JRA-VAN会員ID・パスワード（またはJV-Link利用キー）をコード中にハードコードしてはならない。

- 環境変数での管理を基本とし、以下の変数名を提案する。
  - `JVLINK_MEMBER_ID`
  - `JVLINK_PASSWORD`
- リポジトリには**値を含まない**`.env.example`を追加し、必要な環境変数の名前・形式のみをドキュメント化する（実際の`.env`は`.gitignore`で既に除外済み）。
- `要件定義書.md` §7（非機能要件・セキュリティ）、§12.3（JRA-VAN関連の必要情報）と対応する。

## 2. 個人情報の扱い

本ツールが保持するデータは以下のみであり、第三者の個人情報（PII）は含まれない。

- 利用者本人の予想記録・パドック評価・賭け金（該当する場合）
- 公開情報である馬名・騎手名・調教師名・レース結果（JRA-VANが提供する競走に関するデータであり、個人情報保護法上のPIIには該当しない）

## 3. 脅威モデル（ローカル限定）

| 項目 | 内容 |
|---|---|
| ネットワーク露出 | なし。サーバープロセス・待受ポートが存在しないため、リモートからの攻撃面はゼロ。 |
| 認証 | CLI自体に認証機構は無い（単一ユーザー・単一Windowsアカウントでの利用を前提）。 |
| 残存リスク | PCまたはWindowsアカウントを複数人で共有する場合、ローカルファイル（DB・CSV・環境変数）への他ユーザーからのアクセスリスクが残る。個人利用前提のため優先度は低いが、共有PCでの利用時は`data/`配下のアクセス権限確認を推奨。 |

## 4. JRA-VANデータの二次配布制限

要件定義書 §8（制約・リスク）の再確認。

- JRA-VANデータの二次配布・商用利用は規約上不可。個人利用に限定し、外部への公開・販売・再配布は行わない。
- `.gitignore`で以下を除外済み（実データのコミット防止）。
  - `data/*.db`, `data/*.sqlite`, `data/*.csv`
- 本ドキュメント一式の図・モックアップに登場する馬名等は、`MockDataSource`のサンプルデータと同様にすべて架空のものであり、実在するJRAのレース・馬とは無関係。

## 5. Git衛生

- 本プロジェクトは2つのリモート（`origin`=Backlog、`github`=GitHub）にpushしている。
- **確認結果（2026-08-07、GitHub API `GET /repos/s1f102103707/-paddock`にて確認）**: GitHubリポジトリ `s1f102103707/-paddock` は **`"private": false`（公開リポジトリ）** であることを確認した。現状コミットされている内容（設計ドキュメント、モックデータ、コード）に実データや秘匿情報は含まれていないため直ちに問題は無いが、公開状態であること自体は利用者に認識しておいてもらう必要がある。非公開にすべきと判断する場合は、GitHubリポジトリ設定から変更が必要（本ツールの範囲外の作業）。
- 将来的な強化案（今回は未対応）: pre-commitフックでのシークレットスキャン（例: gitleaks）導入。

## 6. 依存関係のリスク

現状、`pyproject.toml`が宣言する外部依存はテスト用の`pytest`のみで、実行時の依存はゼロ（標準ライブラリのみで実装）。将来`JVLinkDataSource`実装時に`pywin32`、特徴量処理の拡張で`pandas`等を追加する場合は、バージョンを固定（ピン留め）して`pyproject.toml`に明記すること。
